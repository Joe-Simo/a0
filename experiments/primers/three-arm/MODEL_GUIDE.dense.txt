A0 Dense: `fn NAME T... -> T` followed by prefix expressions. The last statement is the result; the next fn or end closes the function. A single expression may follow the header on its line. Parameters A B ... Z, then p26 onward. Types: u32 (or _), bool, io; arrays u32x4, records (u32,bool), one-field record type (u32). A bare fn NAME infers u32 parameters through the highest used parameter and a u32 result. Preserve the complete shown signature when replacing a function, including unused parameters.
Prefix operations have fixed arity: `add mul A B C` means A*B+C. Earlier IDs and parameters are operands. A line `x EXPR` explicitly binds x; unnamed nodes receive a, b, ..., z, aa, ab, ... in order, skipping explicit IDs and reserved words. A keyword, type-like or function name used as an ID needs $ in definitions and references, e.g. `$add`. A shown expression's nesting is meaningful; do not treat it as a flat instruction.
add sub mul and or xor (bool too) << >> (count&31) div (b=0: 4294967295) rem (b=0: a) eq ne lt le gt ge (unsigned, -> bool) select c x y. Arithmetic wraps modulo 2^32.
F a... calls F; call F a... explicitly calls an operation-named function. fold F n s a... starts state=s; for i<n, state=F(state,i,a...). loop P F n s a... checks P(state,i,a...) before each iteration and stops when it is false. An inline body {EXPR; EXPR} uses A=state, B=index, C...=extra operands.
[a b] is an array, [x;N] repeats one literal or parameter a positive N times, (a b) is a record, (a,) is one field; a quoted string is a UTF8 byte array. Aggregates are nonempty. get a i (i mod N), set a i v, at r k, put r k v read/update arrays/records. Operands can be nested expressions.
EDIT: reply bare edit lines. `x EXPR` replaces x or inserts before the result; `x EXPR @ y` inserts after y. -x deletes x; ret EXPR changes the result. fn NAME ... adds/replaces a whole function; -fn NAME removes one. Copy a shown e handle for function edits or the g handle for program edits onto its own line before those edits. Signed specs: +ex/-ex ARGS -> RESULT; +pre/-pre EXPR; +post/-post EXPR. A pre/post is one operation over parameters (and r in post); call a helper for more. Preserve signatures and unaffected behavior.
