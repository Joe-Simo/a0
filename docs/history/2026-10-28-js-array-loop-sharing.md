# Share pure work across JavaScript array-loop predicates and bodies

Small pure loops with runtime bounds and flat-array state now inline their predicate and body. Identical pure expressions may share a value across that boundary until an array write. The existing initializer-copy and per-update ownership proofs remain in force; a returned borrowed extra is copied as in the ordinary owned helper. Constant-bound loops, strict profiles, calls, effects, records and larger bodies retain ordinary lowering. Expression identities use compact interned tokens to avoid expanding repeated expression trees.

The unchanged isort256 benchmark measured 28917.510 ns before and 25128.186 ns after, versus 14785.173 ns for handwritten JavaScript, using 15 interleaved samples. Before samples ranged from 27525.533 to 35815.955 ns and after samples from 23661.422 to 26548.408 ns; maximum recorded load was 0.91. This is a bounded improvement on this host, and the handwritten implementation remains faster. See [raw measurements](../../results/js-array-loop-inline.json).

Emitted JavaScript grows from 6252 to 7172 bytes. Median import times were 0.543049 and 0.564942 ms. Peak RSS was 41364 and 41180 KiB; retained array-buffer measurements were 3225851 and 3396859 bytes. These process and GC measurements are noisy; no startup or memory improvement is claimed. The same report includes heap256, rle4k and minmax1k controls, whose emitted modules are identical. The [emission audit](../../results/js-array-loop-inline-audit.json) checks all 29 stock kernels: only isort256 JavaScript changes after version normalization; C and Linux/Darwin x86 output stay unchanged.

An inline-only experiment did not improve sorting. A broader shared-expression experiment made constant-bound heap256 slightly slower while increasing its code size. Both experiments are preserved in the milestone evidence archive and are excluded from the retained implementation. The retained scope is runtime-bound loops; no benchmark names or algorithm substitutions are used.

Focused tests cover complete sorted arrays, unsigned boundary values, randomized inputs, caller snapshots, aliased extras, reads of old states, borrowed returns, zero trips, boolean lanes, strict/call fallbacks, and the constant-bound exclusion. Full-platform release validation remains outstanding; an available aggregate gate does not authorize publication.
