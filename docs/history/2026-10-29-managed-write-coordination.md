# Coordinated source and artifact persistence

The cache-only fix did not cover other managed writes. CLI source fixes and file outputs, both MCP save modes, and staged source migration now register source and destination owners before rechecking protection state. CLI emission tracks every linked source dependency, while ordinary read-only CLI checks do not retain that ownership bookkeeping or create a writer lease. Destination resolution handles new files and physical symlink parents. This changes write coordination, not source grammar or generated code.

The [evidence report](../../results/managed-write-coordination.json) includes deterministic process and cache races plus public persistence-boundary checks. The latter introduce a synthetic sealing fence when CLI emission, full/compact MCP saves, or source migration reaches the actual filesystem write. The real lease scanner must refuse sealing while that writer is active. CLI coverage includes a separately located source dependency; MCP coverage checks the saved program's result. Existing encrypted-migration tests use ephemeral synthetic identities only.

An initial follow-up omitted a symlink-test import and stopped at typechecking. A later run caught a real no-overwrite regression: leasing an existing migration destination created metadata inside it before rejecting it. The implementation now leases its parent, where the atomic directory rename occurs. The unchanged no-overwrite test passes. Both failed attempts remain in local recovery evidence.

The paired output probe uses unchanged scalar and matrix inputs, C/JavaScript/direct-Wasm targets, and a shared local resource-usage launcher. It disables the A0 artifact cache to isolate CLI output coordination, alternates compiler order and records load. All artifact hashes match. Timing comparisons fall inside the repository's observed-spread bands; some medians are slower. This does not establish zero overhead, the tighter protection budgets, or a memory improvement. The failed measurement setups are retained separately from successful samples.

The earlier cache-only gate lost its supervisor when monitoring was interrupted. Its surviving test process was allowed to finish; completed test summaries and the separately executed remaining checks are preserved without fabricating an official gate pass. The combined checkpoint needs a fresh normal available aggregate gate before it is called validated.

Arbitrary editor writes, shell redirection and external-toolchain temporary-file lifecycles still require explicit treatment. Stale-lease recovery must authenticate the owner and preserve ambiguous/live leases. Public source unification still requires native frontend cost repair and the coordinated migration/tooling cutover. Other protection adapters, independent security/reconstruction review and full-platform release validation remain outstanding. No publication, paid services or real credentials were used.
