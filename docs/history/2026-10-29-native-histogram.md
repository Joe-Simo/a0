# Native vector indices with ordered bucket updates

The next measured gap after native extrema was the existing histogram benchmark. Its fused native loop computed each hash serially before incrementing a bucket. The backend now recognizes a pure bucket-index expression followed by one constant wrapping increment in a power-of-two u32 array. It computes four indices with the existing vector arithmetic emitter, then applies their increments in original order. Colliding indices therefore retain sequential semantics. Dynamic counts, tails, strict profiles, state-dependent indices, other element types and expressions outside the existing register budget retain ordinary lowering. Existing Linux SSE4.1 detection and SSE2 fallback are reused; Darwin emits the SSE2 path.

The [paired runtime report](../../results/native-histogram-runtime.json) uses unchanged stock kernels, argument generation, checksums and iteration counts. Histogram medians were 4399.0559 ns before and 2250.0972 ns after, with 2423.1334 ns on the forced SSE2 path and 1910.9456 ns for Clang native C. Both native paths improve over the checkpoint under the [observed-spread rule](../../results/native-histogram-summary.json). The Clang comparison is a tie within the broad band, with a slower A0 median; this does not establish parity or superiority. Sieve and dot product emit identical code and remain controls. Their absolute timings are new samples, not attributed improvements.

The [all-kernel audit](../../results/native-histogram-audit.json) finds only native histogram output changed among the 29 stock kernels. JavaScript and C are unchanged. Histogram executable sections grow from 513 to 1022 bytes, assembly from 2678 to 4840 bytes; the linked executable remains 16344 bytes. Stack allocation remains 4096 bytes, and measured peak RSS is 8944 KiB on both sides. Process startup includes launch and a kernel call; no general startup or memory improvement is claimed.

The [initial compilation report](../../results/native-histogram-cost.json) records unfavorable warm parse-and-emit medians: lexer 18.739107 to 23.955092 ms and histogram 2.811849 to 4.152765 ms, classified as losses. Removing a map allocation from the recognizer leaves all emitted kernel hashes unchanged. The [targeted follow-up](../../results/native-histogram-compile-followup.json), with 31 interleaved warm samples and eleven fresh processes per variant, records lexer parse-and-emit 18.171401 to 18.610349 ms and histogram 2.252222 to 2.015266 ms. Those comparisons are ties. Fresh-process emission is slower in the follow-up (lexer 50.857457 to 56.076536 ms; histogram 16.002636 to 17.638454 ms), also within the observed bands. Both reports are retained; no general compilation-cost improvement is claimed.

Regression coverage checks collisions, wrapping increments, initial array contents, short and remainder counts, non-power-of-two fallback, state feedback, dynamic counts, borrowed initial arrays, optimized and unoptimized execution, and forced SSE2 with fast multiplication poisoned. The stock kernel is checked against its handwritten reference and the interpreter, including strict execution. Darwin emission inspection does not substitute for platform execution. An initial stock-oracle test exhausted its interpreter fuel allowance; its failed log is preserved and the allowance was increased so the actual unchanged kernel could complete.

A scalar four-trip unrolling experiment was rejected: its paired histogram median changed only from 4419.3934 to 4309.3232 ns while code grew. Its patch and raw measurements remain in the local recovery evidence. The first vector attempt did not fit an unnecessarily restricted temporary register budget and emitted unchanged code; that diagnostic run is also preserved. The retained version uses an otherwise unused accumulator for the scatter scratch value, within the existing vector register limit.

The cumulative goal remains broader than these scoped gains. The [older nine-cell scoreboard](../../results/retained-scoreboard.json) remains historical; the [native extrema report](../../results/native-extrema-summary.json) and this new three-cell comparison are separate, current scoped measurements. Sieve, sorting, heap operations, remaining dot-product cost, output size and compilation cost still warrant work. The historical 616-entry ledger is unchanged. The available aggregate gate is required before this checkpoint is called validated. Full-platform release checks remain outstanding, and the specific publication and private-upload approvals remain pending.
