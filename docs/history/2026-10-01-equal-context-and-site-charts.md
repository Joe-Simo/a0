## Session 2026-10-01 (equal context: A0 against seven languages, all with dependency-scoped views)

Why: an outside review pointed out that the large-program cost results (the 40, 400 and 4000-function sections, the headline ratios, "A0 is 27x to 51x cheaper per task" in results/ai-edit-langs8.json) compare A0's dependency-scoped function view with TypeScript, Rust and the other languages being shown the complete numbered file. That measures a workflow (A0's tool selects the context) against a whole-file workflow, not the language. Those rows stay and are now labelled "workflow comparison" (STATUS, results/ai-edit-langs8.json `comparison`, site/gen/page.tpl). This section is the same measurement with equal context selection.

**The view tool** (`tools/scoped-view.ts`, `test/scoped-view.test.ts`, 6 tests). A parse, not a hand-made case: web-tree-sitter with the grammars of @vscode/tree-sitter-wasm (new dev dependencies, plus @types/emscripten and `"emscripten"` in tsconfig `types` for the d.ts) for TypeScript, Rust, Python, Go, Java, C and Ruby. For a target function it prints the function's own source lines, then each direct callee (a bare `name(...)` call to another function of the same file, in order of first call) as a bodyless signature (arm `signatures`: `;`, ` ...`, `; end` per language) or as its whole body (arm `bodies`), under an edit handle, numbered, with the same `PROTOCOL_LINE_EDIT` text as every other non-A0 cell. Edits are numbered against the view and mapped back to file lines (`applyScoped`): signature lines are read-only, an insertion after a signature goes after that function, `+0` goes above the target. The TypeScript call graph is cross-checked against the TypeScript compiler API in the test. Limits: no type checking or name resolution (shadowing, overloads, methods, calls through values and macros are not followed; Ruby calls without parentheses are not seen); one file; no imports, type declarations, comments above a definition or callers; C is parsed with the C++ grammar (the package has no C grammar; the C subset used parses the same); the target is the function the task names (`sumsq`, where A0's program factors the loop into the fold helper `addel` and the other languages inline it). `tools/ai-edit-experiment.ts` takes `A0_EXPERIMENT_SCOPED=signatures|bodies`. C also got the set-C project filler (`tools/edit-langs/c.ts`), so it runs on c, c400 and c4000; self-check ok (every reference passes, every original fails) on b, c, c400 and c4000 for all seven.

**Finding about the tasks that changes what "equal" means.** All 12 originals are self-contained in every one of the seven languages (loops are inline; no fold helpers), so the tool finds an empty callee set for every target: the `signatures` and `bodies` arms are the same 84 prompts, byte for byte (checked), and they are the same prompts on b, c, c400 and c4000 (checked). The scoped language view is the target function alone, 26 to 60 o200k tokens. A0's view is larger because A0's tasks have fold helpers: its view carries the callee signature line and (canonical) the program handle. The two tasks in which A0's helper holds the bug (`bounds`, `checksum`) are one function in the other languages. This favours the languages a little and is not a property of the call-graph tool.

**Method.** Fresh Haiku and Sonnet Agent-tool subagents, one group file per representation per set (12 tasks, system text once), one shot, then one repair by a fresh subagent per model and group given the system text, request, first reply and the harness's exact rejection; no author-written replies; at most 6 subjects at a time, scoring at most 2 processes. Arms: A0 canonical (`MODEL_GUIDE.rules-merged.txt`, scoped view plus program handle `g0` in deps scope), A0 dense lean with callee bodies (`MODEL_GUIDE.dense.txt`, `A0_EXPERIMENT_DENSE_VIEW=bodies`), and the seven languages with the scoped view. Every arm was collected separately on each of b, c, c400 and c4000 (fresh subjects each time: 4 samples of 24 trials per cell, 96 pooled). The language and dense prompts are identical across the four sets, so the sets are four independent samples, not four tasks; A0 canonical differs by the function-count comment of the program handle. Disclosures: one Haiku canonical subject on c4000 left `checksum-poly` unanswered; a fresh Haiku subject was asked that one task and its reply is the first reply (`results/ai-edit-experiment.c4000.haiku-scoped-a0.replies.json`). Results `results/ai-edit-experiment.{b,c,c400,c4000}.{haiku,sonnet}-scoped-{a0,dense,langs}.json` (+ `.replies.json`: first reply and repair), summary `results/ai-edit-scoped.json` (`tools/ai-edit-scoped-summary.ts`). Cost per task as in "No primer and lazy primer": o200k tokens, system text 1.25x on a cold first call (1 task), 0.17x on the first call of a task in a 10-task session, 0.05x on repairs and in an unbounded session, task + view, repair messages and replies 1x; ties within 1%.

**How much of the earlier advantage remains** (results/ai-edit-scoped.json). The earlier "A0 is 27x to 51x cheaper per task at 400 functions" was the whole numbered file (10.3k to 15.7k tokens) against a view of a few hundred. With equal context A0 canonical is 1.2x cheaper than TypeScript on one cold task at 400 functions (319 against 382), and no language's view grows with program size either, so program length no longer matters for any of them. For A0 canonical, once the primer is cached it is 0.7x to 0.8x: it costs 10% (Java) to 35% (Ruby) more than the languages per task in a 10-task session (190 against 141 to 172) and 21% (Java) to 53% (Ruby) more unbounded (176 against 115 to 145), because its view is larger (a program handle and a callee line) and its failures cost repairs. For A0 dense the advantage is 1.16x to 1.71x on every row (cold 273 against 375 for Ruby and 386 for TypeScript, up to 468 for C; 10-task 117 against 141 and 163; unbounded 99 against 115 and 138), plus higher acceptance. So: the 27x to 203x headlines are workflow comparisons and are not a language property; with equal context A0 canonical keeps a 1.18x to 1.47x cold-task lead (the primer is shorter: 118 against 207 to 275) and loses once the primer is cached, and A0 dense leads on every row by 1.16x to 1.71x. The dense lead comes from three measured things: a primer of 145 against 207 or more, a smaller view (no handle, no program handle; 70 tokens of context against 85 to 108), and fewer repairs (one shot 96/96). Part of it is the line-edit text the languages must carry (about 160 tokens in every call); a language could ship a shorter edit protocol, which this measurement does not try.

**Every loss of A0 canonical (pooled; all but the first two are in sets where a language was better):** 10-task and unbounded cost against all seven languages; acceptance after repair 92/96 against TypeScript, Rust, Python, Go, Ruby 96/96, Java 93/96, C 95/96 (four Haiku misses: `bounds` three times, `checksum` once: the bug sits in the fold helper, which the canonical `deps` view shows as a signature; the dense `bodies` view fixes it); one shot 89/96 against 90 (TypeScript), 92 (Rust, Go, C) and 96 (Ruby). **Losses of A0 dense:** none on cost or acceptance in any set, at 24 trials per cell per set (a one-trial change in acceptance moves a cost by about 8 tokens). **Where the languages fail** (not A0's loss, for the table's context): Python/Haiku 68/96 one shot (28 of its 48 first attempts wrote replacement text without the indentation; repaired to 96/96, the repair costs a call); Java 93/96 (Sonnet inserted a stray `}` on the three create tasks on c); C `pctof` (Haiku division by zero); Rust/Sonnet three first-shot stray `}`.

**What this does not show.** One subject per cell per set; Haiku swings of 2 to 4 tasks per set are within subject variance, and each language is one hand translation. Twelve tasks, u32 arithmetic only; tasks where the language's functions call each other (where the callee arms differ) are not in the set, so the `bodies` arm is exercised only by the tool's unit tests. The numbered line-edit protocol is a handicap in indentation-significant languages that a real tool could remove (apply the view's indentation automatically). `gate`: lint, typecheck and these tests below; x86-64 steps are blocked while Rosetta is stuck.
