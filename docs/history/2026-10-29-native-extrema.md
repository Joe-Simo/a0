# Native unsigned extrema reductions

The existing minmax benchmark remained a substantial native loss after the earlier loop work. Its two unsigned extrema carried in a record still executed scalar compares and selections. The backend now recognizes two independent unsigned extrema over the same pure lane expression, reuses the existing vector expression emitter, and reduces the lanes into the original initial values. This applies to structural min/max patterns, not benchmark names. Strict profiles, dynamic counts, remainders, state-dependent expressions and unsupported register pressure retain their existing lowering.

The [paired runtime report](../../results/native-extrema-runtime.json) uses unchanged stock sources, arguments, checksums and iteration counts. Across fifteen interleaved samples after three warmups, native minmax changed from 1277.0962 to 276.1108 ns per call. Clang's native C result was 141.051 ns, so a material loss remains. The [summary](../../results/native-extrema-summary.json) classifies the improvement beyond the observed-spread band, while the forced SSE2 result of 987.8241 ns is a tie under that rule. Dot product and histogram are identical-code controls. The maximum recorded one-minute load across runtime and compilation measurements was 0.73. These scoped results do not replace the historical 616-entry ledger or establish a universal win.

Linux reuses the existing atomic cached SSE4.1 capability check; the fallback uses SSE2 signed comparisons after sign-bit bias. Darwin emission uses the SSE2 path. Tests execute unsigned edge values, arbitrary initial records, reversed and inclusive comparisons, both extremum orders, equal operators, zero and short loops, tails, dynamic counts, strict semantics and state feedback. They poison unavailable fast instructions in the forced fallback and exercise simultaneous first calls with six live scalar arguments. Darwin emission inspection is not Darwin execution validation.

The [all-kernel audit](../../results/native-extrema-audit.json) finds only native minmax changed across the 29 stock kernels; JavaScript and C are unchanged. Minmax executable sections grow from 481 to 1246 bytes and assembly text from 2583 to 6013 bytes. The linked executable remains 16344 bytes, the measured stack allocation remains 4096 bytes, and median peak RSS remains 7944 KiB. Startup samples include launch and a benchmark call; no startup or memory benefit is claimed.

The [compilation report](../../results/native-extrema-cost.json) includes the lexer, checker, generated corpus and eight stock kernels. Minmax fresh-process emission changes from 13.056079 to 14.517673 ms; checker emission changes from 286.712839 to 293.874958 ms, with identical checker output size. These costs and noisy cold-process controls are retained in full rather than advertised as compilation wins. Measurements use compiler tag 0.1.76; the retained compiler increments to 0.1.77, with a separate version-only output control.

Two preceding experiments were rejected: materializing boolean selections had inconclusive runtime benefit, and scalar record-state allocation did not improve the targeted decoder and enlarged its linked executable. Their patches and raw measurements are preserved locally for the recovery archive.
