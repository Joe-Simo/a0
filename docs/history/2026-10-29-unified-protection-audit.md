# Unified language and protection: audit and cache-writer candidate

The owner's requirement is one public language, not separate recommended Canonical and Dense workflows. The current parser routing, MCP defaults and LSP formatting still expose both. The complete implementation contract and acceptance gates are in [UNIFIED-REQUIREMENTS](../UNIFIED-REQUIREMENTS.md). The existing flat-source parser, native experiment and lossless migration infrastructure remain incomplete; recorded native cost regressions and pending tool integration prevent calling the cutover validated. Replaying existing studies is not a new model-accuracy trial.

Source protection already has an experimental JOSE/WebCrypto implementation. Distributed protection is currently direct-Wasm artifact hygiene, not application encryption or demonstrated algorithm secrecy. The existing threat model in [PROTECTION](../PROTECTION.md) remains applicable, including plaintext access by authorized processing, key-loss and old-copy limits. No real user identity or credential was created.

The [candidate evidence](../../results/protection-writer-candidate.json) reproduces the previously recorded late-cache-write race against the preserved baseline: an in-flight compilation resumes after the source project is fenced and writes plaintext to an external cache. The candidate registers a writer lease before checking the fence, associates CLI caches with their source file, and refuses seal completion while a writer is active. A compilation uses one lease for its write batch; failure drains started writes before release, and the write capability closes with the batch. Lease metadata contains no source or keys. Stale leases fail closed; recovery policy remains pending.

Focused tests cover the delayed lookup, external cache, another process holding a lease, real synthetic-identity seal migration, failure cleanup and closed/drained batches. Product outputs remain byte-identical in the stock target controls. This is a cache-coordination improvement, not complete protection against every in-flight writer: editor saves, artifact output and library integrations still need coverage.

Initial per-entry leases produced an unfavorable heap cold-cache median. Batching reduced that overhead in a follow-up, but the final paired run still has slower medians on some cells. All samples and their scope are retained; protection overhead targets and general startup/runtime/memory claims are not established. The candidate requires a fresh available aggregate gate before it is called validated. Full-platform, independent security and reconstruction reviews remain outstanding. No publication, private upload or paid service was used.

The initial aggregate attempt failed typecheck and build in the new cross-process test's dynamic `node:events` import. Earlier runtime tests had run emitted JavaScript despite that TypeScript error. The failing run is preserved and was stopped after the confirmed error. The test now uses instance event methods; fresh no-emit typecheck, build and focused execution pass. Product cache/lease code and its recorded timings are unchanged by this correction. A fresh aggregate run remains required.
