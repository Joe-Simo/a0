# Bounded native loop inlining

A fresh native measurement of the existing UTF-8 benchmark exposed a large gap that was not a native row in the historical ledger. The decoder's step exceeded a separate 48-own-node inlining limit even though it fit the existing 96-expanded-node loop budget. Its out-of-line call copied the 4096-word read-only input for every byte. Removing the redundant smaller limit allows the existing inliner to reuse the caller's value directly. The expanded-node budget still includes nested inlining; the eight-node ordinary-call budget, six-level depth limit, ownership rules and strict trapping frames remain unchanged.

The [paired runtime report](../../results/native-inline-runtime.json) uses unchanged stock kernel sources, the stock argument generator and checksum, and 1024 driver calls per sample for every variant. It records fifteen interleaved samples after three warmups. The native UTF-8 medians were 1603846.577 ns before, 37958.090 ns after, and 22047.215 ns for the C backend compiled by Clang with native optimization. This is a confirmed improvement over the current checkpoint under the repository's observed-spread rule, while remaining a loss against C. The timed modules carry compiler tag 0.1.75; final 0.1.76 outputs were verified identical apart from that tag. Tokenization and heap sort are identical-code controls and remain ties against the checkpoint; see the [summary](../../results/native-inline-summary.json) for all classifications.

The cost is explicit: UTF-8 executable sections grow from 2785 to 3345 bytes, while the complete linked file stays 16352 bytes. Assembly text grows from 9437 to 11796 bytes. The [compile-cost report](../../results/native-inline-cost.json) records a fresh-process UTF-8 emission median of 26.527 ms before and 30.842 ms after. It also includes gen100 and seven stock kernels. The [additional compiler-sized probes](../../results/native-inline-compiler-cost.json) expose broader costs: lexer assembly grows from 67583 to 76457 bytes and checker assembly from 831498 to 892082 bytes; fresh checker emission rises from 272.997 to 303.670 ms. The checker process peak rises from 119268 to 124588 KiB. These are retained costs, not free improvements. No general compile-speed, memory or process-startup benefit is claimed. The startup probe includes a kernel call, so its lower time must not be described as faster module loading.

The [all-kernel audit](../../results/native-inline-audit.json) finds only native UTF-8 emission changed beyond the version banner among the 29 stock kernels; JavaScript and C outputs are unchanged. Tests cover the 48/49 and 96/97 node boundaries, expanded nested callees, ordinary-call limits, strict frames, zero trips, wrapping state, and the full decoder against both the interpreter and handwritten reference.

Earlier boolean/select and range-propagation experiments produced small size reductions but inconclusive runtime results and are not retained. Their patches, measurements and tests remain in the recovery archive. An initial stock-size native UTF-8 benchmark was stopped during warmup after observing roughly half a minute per sample; it supplies no completed timing claim. The bounded comparison above preserves its kernel and argument generator and uses the same iteration count for all variants.

The available aggregate gate is required before this checkpoint is considered validated. The historical 616-entry ledger is unchanged. Full-platform release validation remains outstanding.
